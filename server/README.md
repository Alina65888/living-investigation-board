# Командная версия на Cloudflare

Сервер для командной работы: вход по email и паролю, роли «Администратор» и «Участник», общая база, сдача и проверка результатов, проблемы, уведомления, обсуждения и файлы к задачам.

Сайт и API работают как один Cloudflare Worker:
- `../docs` — тот же интерфейс, что на GitHub Pages;
- `src/worker.js` — API `/api/*`;
- база — Cloudflare D1, файлы — Cloudflare KV.

Для небольшой команды хватает бесплатного тарифа Cloudflare. Банковская карта не нужна.

## Вариант 1. Автоматически через GitHub (рекомендуется)

После настройки каждое слияние в `main` само обновляет командную версию.

1. **Зарегистрируйтесь** на https://dash.cloudflare.com/sign-up. Нужны только email и пароль.
2. **Узнайте Account ID.** Откройте https://dash.cloudflare.com → раздел **Workers & Pages**. Справа будет строка **Account ID** — скопируйте её.
3. **Создайте API-токен.** Перейдите на https://dash.cloudflare.com/profile/api-tokens → **Create Token** → шаблон **Edit Cloudflare Workers** → **Use template**.
   - В блоке **Permissions** нажмите **+ Add more** и добавьте **Account → D1 → Edit**.
   - В **Account Resources** выберите свой аккаунт.
   - Нажмите **Continue to summary**, затем **Create Token** и скопируйте токен. Он показывается один раз.
4. **Добавьте три секрета в GitHub.** В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret** и создайте:
   - `CLOUDFLARE_API_TOKEN` — токен из шага 3;
   - `CLOUDFLARE_ACCOUNT_ID` — Account ID из шага 2;
   - `ADMIN_EMAIL` — ваш email. Только с этим адресом можно создать первую учётную запись руководителя.
5. **Запустите развёртывание.** Вкладка **Actions** → **Deploy team server** → **Run workflow**. Через 1–2 минуты в журнале шага **Deploy** появится адрес вида `https://living-project-hq.<ваш-поддомен>.workers.dev`.
6. **Откройте этот адрес.** Появится экран «Первый вход»: укажите имя, email из `ADMIN_EMAIL` и пароль.

## Вариант 2. Вручную со своего компьютера

Нужен Node.js 20 или новее.

```bash
cd server
npm install
npx wrangler login                     # откроется браузер для входа в Cloudflare
npm run provision                      # создаст базу и хранилище файлов, запишет их id в wrangler.toml
npm run db:init                        # создаст таблицы
npm run deploy                         # опубликует сайт и API, покажет адрес
npx wrangler secret put ADMIN_EMAIL    # введите свой email
```

## Первые шаги после запуска

1. **Войдите** как руководитель (экран «Первый вход»).
2. **Перенесите данные.**
   - В старой версии (ChatGPT или GitHub Pages): **Данные → Скачать копию**.
   - В новой: **Данные → Загрузить копию**.
   - Переносятся проекты, задачи, этапы и связи. Участников и сообщения о проблемах нужно завести заново.
3. **Добавьте людей.** В разделе **Команда** нажмите **+ Добавить человека**, укажите имя, email и роль. Сайт покажет временный пароль — нажмите **Скопировать** и отправьте сотруднику. При первом входе он придумает свой пароль.
4. **Если сотрудник забыл пароль**, откройте его карточку в «Команде», отметьте **Выдать новый временный пароль** и сохраните.
5. **Если человек ушёл**, снимите галочку **Может входить в систему**. Его текущий сеанс сразу завершится.

Имена в поле «Ответственный» должны совпадать с именами участников в «Команде». По ним сервер понимает, чьи это задачи.

## Кто что может

| | Руководитель | Участник |
|---|---|---|
| Проекты, этапы, связи, доска | создаёт и меняет | смотрит |
| Задачи | все: создаёт, назначает, меняет, архивирует | свои: статус, прогресс, чек-лист; новые задачи — только себе |
| Результат | принимает или возвращает на доработку | сдаёт: текст, ссылка, файлы до 10 МБ |
| Проблемы | видит все, отвечает | пишет свои, видит ответы |
| Люди и пароли | добавляет, меняет роли, сбрасывает пароли | меняет свой пароль |

Права проверяет сервер. Если изменить страницу в браузере, лишних прав это не даст.

## Безопасность

- Пароли хранятся только в виде хеша (PBKDF2-SHA256, 100 000 итераций) с уникальной солью.
- Сеанс — cookie `HttpOnly`, `Secure`, `SameSite=Lax`, живёт 30 дней. При выходе, сбросе пароля или отключении человека сеанс удаляется.
- После 10 неверных попыток входа за 15 минут вход временно блокируется. Блокировка действует отдельно для email и для IP-адреса.
- Запросы с чужих сайтов отклоняются.

## Проверка перед выкладкой

```bash
cd server
printf 'ADMIN_EMAIL=boss@example.com\n' > .dev.vars
npm run db:init:local
npx wrangler dev --port 8787            # в отдельном окне
BASE=http://127.0.0.1:8787 npm test     # на чистой локальной базе
```

Тест проходит весь путь: первый руководитель, сотрудники, права, одновременные правки, сдача и приёмка результата, файлы, архив, уведомления, выход.
