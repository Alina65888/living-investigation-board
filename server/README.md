# Командная версия на обычном хостинге (Рег.ру)

Сервер для командной работы: вход по email и паролю, роли «Администратор» и «Участник», общая база, сдача и проверка результатов, проблемы, уведомления, обсуждения и файлы к задачам.

Как устроено:
- работает на любом хостинге с PHP 8.1+ и Apache — в том числе на виртуальном хостинге Рег.ру;
- `../docs` — тот же интерфейс, что на GitHub Pages;
- `public/api/` — PHP-сервер для адресов `/api/*`;
- база — один файл SQLite, ничего создавать не нужно. Если хотите MySQL, это настраивается в `api/config.php`.

Данные (база и файлы) хранятся в папке `living-hq-data` рядом с папкой сайта, а не внутри неё, поэтому из браузера они недоступны.

## 1. Подготовка в панели Рег.ру

1. Откройте **Хостинг** → **Панель управления хостингом**.
2. Проверьте, что в разделе **Сайты** есть сайт `zadachimantckd.ru`. Если его нет, нажмите **Создать сайт** и укажите домен.
3. **Версия PHP.** В настройках сайта выберите **PHP 8.1 или новее**. Если версия старее, сайт покажет «Сайт настраивается» и подскажет, что поменять.
4. **HTTPS.** В разделе **SSL-сертификаты** закажите бесплатный сертификат **Let's Encrypt** для `zadachimantckd.ru`. Выпуск занимает от нескольких минут до часа. После выпуска включите **перенаправление на HTTPS**.
5. **Данные для FTP.** Они в письме об открытии хостинга или в панели в разделе **FTP-пользователи**: сервер (например, `server123.hosting.reg.ru`), логин и пароль. Папка сайта обычно `www/zadachimantckd.ru/`.

## 2а. Автоматическая выкладка из GitHub (рекомендуется)

После настройки каждое слияние в `main` само обновляет сайт.

1. В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте:
   - `FTP_SERVER` — адрес FTP-сервера;
   - `FTP_USERNAME` — логин FTP;
   - `FTP_PASSWORD` — пароль FTP;
   - `FTP_DIR` — папка сайта на сервере, со слешем на конце, например `www/zadachimantckd.ru/`;
   - `ADMIN_EMAIL` — ваш email. Только с этим адресом можно создать первую учётную запись руководителя.
2. Откройте **Actions** → **Deploy to hosting** → **Run workflow**. Загрузка идёт по защищённому FTPS, а если хостинг его не поддерживает — по обычному FTP.
3. Откройте https://zadachimantckd.ru. Появится экран «Первый вход».

## 2б. Вручную через файловый менеджер

1. Откройте **Actions** → последний запуск **Deploy to hosting** → внизу, в блоке **Artifacts**, скачайте **site-for-hosting**. Это zip-архив с готовой папкой сайта.
2. В панели хостинга откройте **Файловый менеджер** → папку `www/zadachimantckd.ru`. Удалите заглушку `index.html` (или `index.php`) от Рег.ру, загрузите архив и распакуйте его в эту папку.
3. В папке `api` скопируйте `config.sample.php` в `config.php` и впишите свой email в строку `'admin_email' => ''`.
4. Откройте https://zadachimantckd.ru.

## 3. Первые шаги

1. **Войдите как руководитель:** на экране «Первый вход» укажите имя, email из настроек и пароль.
2. **Перенесите данные.**
   - В старой версии: **Данные → Скачать копию**.
   - В новой: **Данные → Загрузить копию**.
   - Переносятся проекты, задачи, этапы и связи. Участников и сообщения о проблемах нужно завести заново.
3. **Добавьте людей.** В разделе **Команда** нажмите **+ Добавить человека**, укажите имя, email и роль. Сайт покажет временный пароль — нажмите **Скопировать** и отправьте сотруднику. При первом входе он придумает свой пароль.
4. **Если сотрудник забыл пароль**, откройте его карточку в «Команде», отметьте **Выдать новый временный пароль** и сохраните.
5. **Если человек ушёл**, снимите галочку **Может входить в систему**. Его текущий сеанс сразу завершится.

Имена в поле «Ответственный» должны совпадать с именами участников в «Команде». По ним сервер понимает, чьи это задачи.

## Кто что может

| | Руководитель | Участник |
|---|---|---|
| Проекты, этапы, связи, доска | создаёт и меняет | смотрит |
| Задачи | все: создаёт, назначает, меняет, архивирует | свои: статус, прогресс, чек-лист; новые задачи — только себе |
| Результат | принимает или возвращает на доработку | сдаёт: текст, ссылка, файлы до 10 МБ |
| Проблемы | видит все, отвечает | пишет свои, видит ответы |
| Люди и пароли | добавляет, меняет роли, сбрасывает пароли | меняет свой пароль |

Права проверяет сервер. Если изменить страницу в браузере, лишних прав это не даст.

## Однократное обновление роли (v56)

По запросу владельца после публикации v56 первый запрос к базе назначает роль `admin` существующей активной учетной записи `amullakaeva97@gmail.com`. Обновление выполняет `public/api/role-migrations.php` внутри обычного запуска миграций. Пароль, сеансы и остальные поля учетной записи сохраняются. После успешной публикации достаточно обновить страницу сайта.

Результат записывается в таблицу `role_migrations` с идентификатором `2026-10-18-amullakaeva-admin-v56`: `promoted`, `already_admin`, `skipped_missing` или `skipped_inactive`. Отсутствующая учетная запись не создается, отключенная не активируется. Повторный запуск, последующее изменение роли в «Команда» или создание учетной записи заново не приводят к повторному назначению администратора.

Для обычного изменения или отмены роли используйте «Команда» под другим администратором. Проверка миграции на отдельной базе в памяти: `php server/test/role-migrations.php` из корня репозитория (PHP 8.1+ с PDO SQLite). Проверка включена в процесс публикации; рабочая база при тестировании не используется.

## Резервная копия

- Всё содержимое хранится в папке `living-hq-data` (файл `hq.sqlite` и папка `files`). Время от времени скачивайте её через файловый менеджер.
- Копию проектов и задач можно в любой момент скачать из интерфейса: **Данные → Скачать копию**.

## Безопасность

- Пароли хранятся только в виде хеша (`password_hash`, bcrypt).
- Сеанс — cookie `HttpOnly`, `SameSite=Lax`, а при HTTPS ещё и `Secure`. Живёт 30 дней. При выходе, сбросе пароля или отключении человека сеанс удаляется.
- После 10 неверных попыток входа за 15 минут вход временно блокируется. Блокировка действует отдельно для email и для IP-адреса.
- Запросы с чужих сайтов отклоняются. Папка `api` открыта из браузера только через `index.php`.

## Проверка перед выкладкой

```bash
cd server
cp public/api/config.sample.php public/api/config.php   # впишите admin_email: boss@example.com
npm run dev                                              # http://127.0.0.1:8788, в отдельном окне
BASE=http://127.0.0.1:8788 npm test                      # на пустой базе
```

Тест проходит весь путь: первый руководитель, сотрудники, права, одновременные правки, сдача и приёмка результата, файлы, архив, уведомления, выход. Проверен с SQLite и с MySQL (MariaDB).

## Благодарственные письма (v57)

`letters.php` обрабатывает маршруты `/api/letters`, `/api/letter-templates`, `/api/letter-signature`, `/api/letter-preview`, `/api/letter-render`. Нужны расширения PHP DOM и PDO SQLite (или используемый PDO MySQL). При первом обращении создаются отдельные таблицы `letter_templates`, `letters`, `letter_signatures`, `letter_events` и один встроенный макет МАНТ. Общие задачи и договоры не перезаписываются. Папка `api/letter-assets` нужна для установки встроенного макета; не исключайте ее при загрузке на хостинг.

Сервер проверяет автора/роль, статус и ревизию письма для каждого действия. Только администратор управляет макетами и изображением подписи, согласует или возвращает письмо. Участник видит свои письма и общую библиотеку. Несогласованное письмо нельзя получить через маршрут печати. Подпись фиксируется при согласовании внутри транзакции вместе с новой ревизией, событием истории и уведомлениями. Проверяется также версия изображения подписи. После возврата в черновик прежняя ссылка на печать перестает открывать старую подписанную версию.

HTML-макеты очищаются на сервере. Предпросмотр помещен в iframe без доступа к origin приложения; печатная страница также получает CSP sandbox, разрешающий только встроенный управляющий скрипт с одноразовым nonce и печать. Скрипты шаблона, обработчики событий, формы, внешние изображения/шрифты, произвольные фреймы и перенаправления недоступны. Подпись принимается только как проверенное растровое изображение. Исходник подписи не передается участнику через JSON API, но ее изображение входит в согласованный печатный документ.

Проверки: `php server/test/letters.php`; полный сценарий на отдельной пустой тестовой базе: `BASE=http://127.0.0.1:8790 node test/letters.browser.mjs` (Playwright/Chromium, тестовый `admin_email=boss@example.com`). Браузерный сценарий создает только тестовые аккаунты и подпись «TEST»; не запускайте его на рабочей базе. Проверка верстки/очистки включена в Deploy to hosting.
