# Living Project HQ

Браузерный штаб проектов: задачи, этапы, сроки, зависимости, риски, команда, календарь и живая 3D-доска.

## Возможности

Основная навигация: **Сегодня / Мои задачи**, **Проекты**, **Документы** (для администратора), **Команда**. Уведомления доступны по колокольчику, архив и настройки — в меню. В проектах: Список, Канбан, Календарь; Доска и Связи — в «Других видах». На телефоне основные разделы находятся в нижней панели.

- Руководитель начинает с очереди результатов, вопросов, просрочек и задач без ответственного; все задачи и массовое редактирование доступны отдельной кнопкой.
- Единая форма создания задачи: название, ответственный из команды, срок, текущий проект или Входящие. Результат, проверка и чек-лист раскрываются дополнительно.
- «Завершить» закрывает обычную задачу с возможностью отмены; обязательная проверка всегда открывает форму сдачи. Прикрепление материалов сохраняет текущий статус.
- Комплект документов связан с проектом и задачей. Форма состоит из трёх шагов; повтор сделки очищает номера, сроки, отметку оплаты и привязку к старой задаче.
- Переходы, открытая задача, шаг документов, поиск и фильтры отражаются в адресе; кнопки браузера Назад/Вперёд возвращают контекст.

- обзор текущих действий, рисков и согласований;
- список задач, Kanban, календарь и Timeline;
- проекты с этапами, контрольными точками, участниками и критическим путём;
- командная загрузка и задачи по исполнителям;
- зависимости и автоматическая блокировка следующих задач;
- доска расследования в духе Miro: пробковое полотно, карточки на булавках, заметки-стикеры и подписанные нити связей;
- локальное сохранение, экспорт и импорт резервной копии;
- адаптивный интерфейс для компьютера и телефона.

## Хранение данных

Рабочие данные сохраняются в IndexedDB текущего браузера. Для переноса на другое устройство используется JSON-резервная копия через меню «Данные».

## Разработка

Приложение в `docs` не требует сборки. Исходные файлы:

- `docs/app-v4.js` — проекты, задачи, фильтры и основные режимы;
- `docs/corkboard.js` — общий холст доски: панорама, масштаб, перетаскивание карточек и нити;
- `docs/board-v8.js` — вкладка «Доска»: ракурсы, заметки, редакторы карточек;
- `docs/hq.js` — вкладка «Связи»: зоны проектов и цепочки зависимостей;
- `docs/app-v20.css` — общий стиль приложения: палитра, шрифты, цвета статусов, меню, лента «Сегодня»;
- `docs/investigation-board.css` и `docs/fonts/` — оформление доски и локальные шрифты с кириллицей (PT Sans, Roboto Slab, Caveat, PT Mono; SIL Open Font License);
- `docs/style.css`, `docs/v4.css`, `docs/visual-v8.css`, `docs/dashboard-v12.css` — интерфейс и адаптивность.

## Командная версия

Командная версия работает на обычном PHP-хостинге (Рег.ру) по адресу https://zadachimantckd.ru. Там вход по email и паролю, роли «Администратор» и «Участник», общая база, сдача и проверка результатов, проблемы, уведомления, обсуждения и файлы. Как выложить и настроить — в [server/README.md](server/README.md).

- **GitHub Pages** — личная версия: данные в IndexedDB браузера, ничего не отправляется на сервер.
- **Хостинг** — тот же код `docs` и PHP-сервер `server/public/api/`. Интерфейс сам понимает, где открыт: если рядом есть сервер, он показывает экран входа.
- Руководитель добавляет людей в «Команде» и передаёт им временный пароль. При первом входе сотрудник задаёт свой пароль.
- Права проверяет сервер. Участник меняет статус, прогресс и чек-лист своих задач и сдаёт результат. Удалять и менять чужое он не может.
- Для переноса данных: «Данные → Скачать копию» в старой версии, «Данные → Загрузить копию» в новой от имени руководителя.
- При одновременной работе изменения не теряются: правки исполнителей и принятые результаты сохраняются, даже если руководитель редактировал старую версию данных.
- GitHub Action **Deploy to hosting** выкладывает сайт по FTP при каждом слиянии в `main`.

`docs/workspace-store.js` — общий контракт хранения; `docs/auth-ui.js` — вход и смена пароля; `docs/team-ui.js` — недельный план, команда и проблемы; `docs/task-workflow.js` — результаты, проверка, уведомления, архив.

## Проверка пользовательских сценариев

`npm test` проверяет модули и генерацию документов; `npm run build` собирает статическую версию.

Для браузерной проверки установите Playwright (`npm install --no-save playwright`, `npx playwright install chromium`) и запустите `node test/journeys.browser.mjs`. Сценарии используют локальный сайт, синтетическую команду и подменённые ответы API: создание задачи, проверка результата, вложения, отмена завершения, история переходов, документы из задачи, повтор сделки и скачивание Word на мобильном экране. Реальные аккаунты и рабочие данные не используются. Это проверка интерфейса, а не замена PHP API-тестов из `server/test`.

## Упрощение ежедневной работы

- Обычная задача завершается без отчёта; проверка руководителем включается отдельно при создании.
- Карточка объясняет следующий шаг. Задачи на доработке находятся выше групп по срокам.
- На личном экране после задач показаны открытые вопросы и до трёх последних ответов по решённым вопросам.
- Из задачи можно запросить информацию, помощь или предложить новый срок. Отправка вопроса не меняет статус или срок задачи; руководитель согласует изменения отдельно.
- Руководитель видит задачи со сроками на ближайшие семь календарных дней и может открыть их или изменить срок и ответственного.
- Браузерные сценарии также проверяют запрос нового срока без изменения задачи и недельный обзор. Группировка и подсказки проверяются в `test/task-guidance.test.mjs`.
